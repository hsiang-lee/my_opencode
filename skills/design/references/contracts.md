# 契约式设计（DbC）— 精确语义

回到索引: [../SKILL.md](../SKILL.md)

> 契约是「客户 / 供应者」关系的精确规格：你满足我的前置，我就兑现我的后置。契约不是「多加几处断言」，而是把每次交互建立在相互义务上。

## 1. 三要素

| 要素 | 约束谁 | 何时成立 | 违反意味着 |
|------|--------|----------|------------|
| **前置条件** | 调用方 | 调用前 | 调用方 bug |
| **后置条件** | 实现方 | 正常返回后 | 实现方 bug |
| **类不变式** | 类自身 | 构造后 + 每个公开方法前后 | 类状态被破坏 |

**契约失败 ≠ 可预期的运行错误**：它表示程序里有缺陷，不该被 `catch` 后优雅吞掉、也不该转成用户提示。

## 2. 不变式的精确规则

- 构造器执行完毕后必须成立
- 每个**公开**方法调用前、调用后都必须成立
- 方法**执行过程中**可以暂时打破（先减后加），返回前恢复即可
- 只约束公开方法，不约束私有辅助方法
- 不变式隐式合取到每个公开方法的前置与后置上（= 调用前后自动检查）

好不变式的写法：只写**真正恒定**的属性；多条用 `and` 并列，每条只管一件事；边界取不取得到要想清楚（`0 <= count && count <= capacity`）。

## 3. 继承时的契约规则（LSP 的形式化）

| 项 | 子类规则 | 直觉 |
|----|----------|------|
| 前置条件 | 只能**保持或弱化**（放宽） | 调用更容易被允许 → 换成子类也安全 |
| 后置条件 | 只能**保持或加强** | 承诺更多 → 调用方得到的不会更少 |
| 不变式 | 只能**保持或加强** | 状态约束不能变松 |

口诀：**前弱后强不变强，子类才能替爹上。** 祖先的不变式全部继承。

## 4. 六条从契约推导的 API 原则

1. **CQS** 命令与查询分离：查询返回值不改状态，命令改状态不返回值
2. 基本查询与派生查询分开（派生用基本查询定义）
3. 每个派生查询写后置条件（用基本查询表达）
4. 每个命令写后置条件（规定各基本查询的最终值）
5. 每个查询与命令写前置条件（限定合法调用时机）
6. 用不变式描述恒定特性

合起来：**接口本身即规格** —— 前置 + 后置 + 不变式写全，就能推导出类的全部可观察行为。

## 5. 其他两条 Meyer 原则

| 原则 | 含义 | 落地 |
|------|------|------|
| **UAP** 统一访问原则 | 调用方不应从语法上区分「读字段」和「调计算」 | 属性与查询方法同名同形，改实现不破调用方 |
| **SCP** 单选择原则 | 每个知识/决策只在一处表达 | 即后来的 DRY |

## 6. 契约 → 测试映射

| 契约 | 测试类型 |
|------|----------|
| 前置条件 | 边界值 / 非法输入 / 违约行为测试 |
| 后置条件 | 返回值与状态断言（含 `old` 对比：`balance == old + amount`） |
| 不变式 | 操作序列测试：任意公开方法调用序列后断言不变式 |
| LSP | 同一组测试跑父类与所有子类实现（契约测试） |

## 7. 写不出契约时

写不出前置/后置 = **接口还没想清楚**。回上一步重新划分职责，不要用「参数要合法」「返回正确结果」这类空话糊过去。

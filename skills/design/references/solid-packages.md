# SOLID + 包设计原则

回到索引: [../SKILL.md](../SKILL.md)

## 一、类级五原则

| 原则 | 定义 | 违反信号 | 修正手法 |
|------|------|----------|----------|
| **SRP** 单一职责 | 一个类只有一个引起它变化的原因（= 只对一个角色负责） | 一次需求变更要同时改校验/存取/通知；类名里出现「和」 | Extract Class / Move Method |
| **OCP** 开闭 | 对扩展开放，对修改关闭：加新行为靠新增代码 | 每加一种类型就改同一个 if/else 或 switch | 多态、Strategy、模板方法 |
| **LSP** 里氏替换 | 子类可替换父类而不破坏调用方预期 | 子类抛父类不会抛的异常；子类空实现父类方法；子类加强前置 | 改委托、抽取共同父类、契约收窄 |
| **ISP** 接口隔离 | 客户端不依赖它用不到的方法 | 实现类出现 `throw NotImplemented`；空方法体 | 拆小接口（按客户端拆） |
| **DIP** 依赖倒置 | 高层不依赖低层，两者都依赖抽象；抽象不依赖细节 | 业务层 `new EmailSender()`；高层 import 具体 DAO/SDK | 提取接口 + 构造注入 |

**LSP 的精确形式**（Meyer 契约版）：前置、后置、不变式的继承规则见 `contracts.md`，那里是唯一完整定义。

## 二、包级六原则

### 复用维度（三者互相拉扯，按变化频率权衡）

| 原则 | 含义 | 操作 |
|------|------|------|
| **REP** 重用发布等价 | 重用的粒度 = 发布的粒度 | 一个包 = 一个可独立发布的单元 |
| **CCP** 共同闭包 | 因同一原因变化的类放同一个包 | 一个变更只改一个包 |
| **CRP** 共同重用原则 Common Reuse Principle | 不一起用的类不要放同一个包 | 只用 A 的客户端不该被迫依赖 B |

**张力**：CCP 倾向「放一起」（减少改动波及），CRP 倾向「拆开」（减少无用依赖）。开发期偏 CCP，稳定后偏 CRP。

### 依赖维度

| 原则 | 含义 | 判据 |
|------|------|------|
| **ADP** 无环依赖 | 包依赖图不允许有环 | 依赖图能拓扑排序 |
| **SDP** 稳定依赖 | 依赖箭头指向更稳定的包 | 只依赖比自己更稳定的包 |
| **SAP** 稳定抽象 | 越稳定的包越抽象 | 稳定包内抽象类/接口占比高 |

**稳定度 I = 出向依赖数 /（入向 + 出向）**：I 越小越稳定。稳定包应抽象（I 小 + A 大），不稳定包应具体。

## 三、评审时的四问

1. 这个类是否只有一个变化原因？（SRP）
2. 加新行为是否需要改老代码？（OCP）
3. 依赖箭头是否指向更抽象、更稳定的一方？（DIP / SDP / SAP）
4. 包依赖图是否有环？（ADP）

违反其中任何一条，先问「变化是否已经发生」，再决定要不要改 —— 未发生的变化不值得提前抽象。

# 重构执行流程

回到索引: [../SKILL.md](../SKILL.md)

## 两顶帽子 (Two Hats)

重构与加功能是两顶不同的帽子，**同一提交内只能戴一顶**：

| 帽子 | 做什么 | 测试变化 |
|------|--------|----------|
| 重构 | 只改结构，不改行为 | 测试条数不变，断言不变 |
| 加功能 | 改行为 | 先加红色测试 |

**判定**：如果本次改动让某个测试的**期望值**发生变化，那就是加功能，不是重构。

**红线**：重构过程中发现需要新行为 → 停下，切帽子，先加测试再改。

## 执行流程 (Execution Flow)

在 TDD 绿色阶段通过后（所有测试通过），story-executor 使用本流程执行重构：

```
1. 确认所有测试通过 (GREEN confirmed)
   │
2. 所有测试通过？──否──► 停止。修复代码。不进入重构。
   │是
3. 按 SKILL.md「台账必填项」与 `smells-catalog.md` 逐类人工核对，逐项产出：命中 → 处置（`fixed` / `deferred` + `OPEN_ITEMS` 目标 / `retained` + 例外引用）；范围外只能 `deferred`，不得以级别跳过
   │
   4. 发现坏味道？──否──► 该项记入台账（未命中+理由一句），核对下一项。
   5. 按 `smells-catalog.md` 的「首选手法」选择对应重构技术
   │
   6. 应用重构：仅做结构性变更，不改变行为
   │
   7. 运行所有测试
   │
   8. 测试通过？──否──► 回滚本次重构改动，台账对应项标注「已回滚: 该步重构导致测试失败，附详情」后停止继续重构。返回外层。
   │是
   9. 还有未处置命中？──是──► 回到步骤 3（一次只处理一种）
   │否
   10. 输出 REFACTOR_LEDGER（格式见 SKILL.md「台账必填项」）。返回外层。
```

### 执行规则

- **一次一种坏味道。** 每次只应用一种重构技术，验证通过后才处理下一个。
- **不变更行为。** 重构只改变结构：不添加新功能、不改变既有公开契约；若必须新增接缝/接口，单列一步并说明。
- **测试通过后才继续。** 任何一步测试失败 -> 回滚该步 -> 报告 -> 停止。

## 错误处理

| 场景 | 处理方式 |
|------|----------|
| GREEN 后测试失败 | 不进入重构。先修复生产代码。 |
| 重构步骤导致测试失败 | 回滚该单步重构改动，台账对应项标注「已回滚: 该步重构导致测试失败，附详情」，停止继续重构，返回外层。 |
| 检测到多种坏味道 | 一次处理一种。每一步独立验证。 |
| 未检测到坏味道 | 台账该项写「未命中 + 哪条判据不成立」（不写「看着没问题」）。返回外层。 |

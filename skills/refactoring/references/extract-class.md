# Extract Class 操作手册

回到索引: [../SKILL.md](../SKILL.md)

> 仅在命中「过大类 / 数据泥团 / 依恋情结 / 发散式变化」并选定 Extract Class 时加载。
> 行为保持：只搬结构，不改行为。新增校验、新增方法都属于 Feature。

## 1. 识别数据簇

仅在 smells-catalog 已命中「过大类 / 数据泥团 / 依恋情结 / 发散式变化」后使用本节：对目标类字段逐组核对，命中任意一条即为候选簇（本节只做组内细分，不替代坏味道命中判定）：

| 判据 | 可操作标准 |
|------|-----------|
| 领域语义 | 整组能用一个领域名词概括。常见子概念：地址（country/city/street/zip）、时间范围（start/end/timeZone）、金额（amount/currency/rate）、配置（maxRetries/timeout/enabled）、联系方式（name/phone/email）、尺寸（width/height/unit） |
| 共同变化 | 改 A 必须同步改 B 才正确。佐证：同一方法里成对赋值；同一 commit / 历史修复中成对出现 ≥2 次 |
| 共同访问 | 同一组字段在 ≥2 个方法中同时被读写，或作为同一函数的参数出现在 ≥2 处 |
| 不变量 | 见第 2 节。不变量涉及的字段必须整体进入同一簇，不可拆开 |

反向条件：两个字段各自独立变化、无共同读写、无共同约束 → 不属于同一簇。

## 2. 不变量扫描（拆分的硬边界）

| 类型 | 示例 |
|------|------|
| 范围约束 | startDate ≤ endDate |
| 总和约束 | Σ itemCounts = totalCount |
| 互斥 / 条件约束 | status = active ⇒ activatedAt 非空 |
| 格式约束 | phone 匹配正则（**单字段自身约束，不构成分簇理由**） |

发现方法：逐字段问「它变化时是否必须同步改另一个字段」；再查历史 bug 与修复 commit 中成对出现的字段。

## 3. 四道闸门（任一不过 → 不拆）

1. **命名**：能用一个领域名词概括；命名失败 → 放弃该簇。
2. **不变量完整**：同一不变量涉及的字段必须全部进同一新类。
3. **反向依赖为 0**：新类方法访问原类成员的数量必须 = 0；否则先 Move Method / Extract Method 切断，再拆。
4. **体量 / 贫血**（两问独立，任一命中即为不通过）：
   - **贫血**：新类只有字段 + getter/setter，没有任何真实行为（校验、计算、比较、格式化）→ **不拆**（不论行数），改用 Introduce Parameter Object 或就地封装。含既有不变量校验即算真实行为。
   - **过大**：预计规模超过本语言「过大类」线（见 SKILL 阈值表；C++ 500 行）→ 簇划太大，回第 1 节重划，不是放弃。
   - 参考线：C++ 中 <100 行且无行为，通常就是贫血情形，按第一条处理。

## 4. 七步执行

1. **基线**：目标测试 + 全量命令与 `N passed`，并快照 public API 签名。
2. **建新类**：选中字段私有 + 全参构造 + 只读访问；已有不变量校验原样搬入，不新增。
3. **原类换引用**：删除被提取字段，改为持有一个新类字段。
4. **更新访问点**：原类内先委托，保持 public API 不变。
5. **移动方法**：只移动「只使用该组字段」且非 public 的方法；混用原类与新类字段 → 先 Extract Method 分离再移。public 方法保留委托壳，函数体搬到新类。
6. **验证**：目标测试 + 簇收尾全量；期望值不变，public API diff 为空（或单列一步并说明）。
7. **记账**：按第 6 节产物写入台账；重扫原类，仍命中过大类 → 记 `NEW` 回循环。

## 5. 行为保持红线

- 已存在的不变量校验原样搬入新类；**新增**校验属 Feature，另开任务。
- 同一 commit 不改公共 API；调用方迁移必须另起一步。
- 一次只拆一个簇；不把多个簇混进同一轮。
- 不为拆而拆：拆出只有 getter 的类、再往里塞业务逻辑 = 新增行为。
- 拆完测试红 → 回滚该步，不许改测试迁就。

## 6. 强制产物（缺项 = 未完成）

```
EXTRACT_CLASS:
- 目标类 / 命中坏味道 + 证据
- 字段簇: <字段> @ file:line（命中的判据 + 不变量类型）
- 新类: <领域名词> — 职责一句
- 闸门: 命名 ✓ / 不变量 ✓ / 反向依赖 0 / 体量 ✓
- 移动方法: <list>
- public API: 不变 | 差异
- 验证: <命令> → N passed
```

## 7. 反例

- 拆出 3 个 getter，原类仍 800 行：簇选错，或没移动方法。
- 新类方法里出现原类引用：双向耦合，反向依赖闸门没把住。
- 拆出的类只有数据：贫血模型，应改用参数对象或放弃提取。
- 拆完测试红：回滚该步，不许改期望值。

# 遗留代码 — 接缝与特征测试

回到索引: [../SKILL.md](../SKILL.md)

> **定义：没有测试的代码就是遗留代码** —— 无论它多新、多漂亮。
> **核心：没有安全网就不改。先解依赖，再重构，最后才改行为。**

## 1. 三个基础概念

| 概念 | 含义 |
|------|------|
| **接缝 Seam** | 不改动原位置就能改变行为的地方 |
| **特征测试 Characterization Test** | 不测「应该是什么」，只锁定「现在实际是什么」 |
| **依赖 Dependency** | 阻止隔离测试的障碍（硬编码、全局状态、内部 new、静态调用、环境读取） |

## 2. 接缝三类型

| 类型 | 机制 | 本项目形态 | 优先级 |
|------|------|------------|--------|
| 对象接缝 | 多态 / 接口替换实现 | 虚函数 + 构造注入 | 首选 |
| 链接接缝 | 换链接库改变行为 | 测试链接替身实现 | 次选 |
| 预处理接缝 | 宏 / 条件编译 | `#ifdef` / `-D` | 最后手段 |

优先对象接缝的理由：类型安全、编译期可查、不污染生产代码；预处理接缝会把测试关切写进产品源码。

## 3. 安全修改五步

```
1. 识别修改点 → 列出它触达的全部依赖
2. 找接缝   → 在修改点附近找可插入测试的位置（按三类型优先级）
3. 写特征测试 → 锁定当前行为（包括看起来错误的行为）
4. 解依赖   → 用 legacy-techniques.md 的技术，一次解一个
5. 小步修改 → 每步跑全部测试，绿了再下一步
```

**顺序不可颠倒**：先改代码再找测试 = 没有安全网的高空作业。

## 4. 特征测试

### 何时写

- 修改前，目标代码没有现成测试
- 重构前，需要安全网
- 修 bug 前，先锁住「现在错在哪」

### 五步

1. 定目标方法（从最稳定的公共入口开始）
2. 构造最简单的输入（典型值 + 边界值：null / 空集合 / 0 / 最大值）
3. 调用，记录实际返回值 / 副作用
4. 把记录值写成断言
5. 命名 `locks_current_<行为描述>`

### 三条陷阱

| 陷阱 | 应对 |
|------|------|
| 断言值来自实际运行，不代表正确 | 只当安全网，不当规格；发现疑点另开 bug 记录 |
| 特征测试失败可能是测试写错 | 先怀疑测试，再怀疑代码 |
| 不理解新行为前删除旧特征测试 | 新行为有测试覆盖后才可删 |

### 覆盖策略

不要试图一次覆盖全部路径。先覆盖**即将修改的那条路径** + 它的直接调用者；其余分支记入 debt-ledger。

## 5. 四条铁律

1. 改行为之前必须先有特征测试锁住现状
2. 每次改动极小，改完立刻跑全部测试
3. 解依赖（结构）与改行为（语义）分两次提交
4. 特征测试的当前输出 ≠ 正确规格

## 6. 常见陷阱汇总

| 陷阱 | 后果 | 应对 |
|------|------|------|
| 边解依赖边改行为 | 失败后无法定位是结构还是语义 | 两次提交，先结构后语义 |
| 一次解多个依赖 | 同上 | 一次一个 |
| 只覆盖快乐路径 | 改动后边界崩了不知道 | 补 null / 空 / 边界 |
| 用 `#ifdef TEST` 开路 | 产品代码被测试污染 | 优先对象接缝 |
| 特征测试写完就删 | 失去回归保护 | 保留直到新行为有测试 |

# Brainstorm — 设计探索方法

通过对话澄清需求、探索方案、逐步确认设计。

## 提问澄清

聚焦理解四件事：

| 维度 | 问题 |
|------|------|
| 目的 | 为什么做这个？解决什么问题？ |
| 约束 | 时间、技术栈、兼容性要求？ |
| 成功标准 | 怎么知道做对了？ |
| 范围 | 什么明确不做？ |
| 结构归属 | 这些数据类拥有自己的操作吗？新操作的归属按"谁拥有它需要的数据"回答了吗？ |
| 架构债 | 本次涉及文件在 debt-ledger 有登记的债吗？是否收编？ |

**方式：** 优先选择题，也欢迎开放式回答。

**反模式：** 一次问多个、模糊问题、跳过问题直接设计。

---

## 提出方案

提出 **2-3 个方案**，每个含：描述 / 优势 / 劣势，并按 开发时间 · 复杂度 · 维护成本 · 风险 四维对比。

**YAGNI：** 删除不必要功能，MVP 优先。模式同理：不为"以后可能要"引入抽象。

---

## 输出：决策清单

产出**决策清单**，与 Feature Step 1 的格式一致（对话中给出，不单独写文档）：

```markdown
## 决策清单

**目标**（1-3 行）
**非目标**（1-3 行，明确不做什么）

### 对外接口与契约
| 接口 | 前置条件 | 后置条件 | 不变式 | 错误语义 |
|------|----------|----------|--------|----------|
| `IX.foo(a) → B` | a 非空 | 返回 ≥0 | — | 非法输入抛 E |

### 关键选择
| 选择 | 理由 |
|------|------|
| ... | ... |

### 未决项
- 无 / [条目 + 待谁裁决]
```

| 要素 | 是否进决策清单 |
|------|----------------|
| 目标 / 非目标 | ✅ 必需 |
| 对外接口 + 前置/后置/不变式 | ✅ 必需（唯一的前置设计） |
| 关键选择 + 理由 | ✅ 必需（含范式判定：状态型 OO / 数据变换 FP） |
| 错误语义 / 边界 | ✅ 必需 |
| **类怎么拆、组件划分、模式选型** | ❌ 不进——留 REFACTOR 由测试压力逼出 |
| 数据流细节 | ⚠️ 仅在影响契约时写一句 |

**红线**：契约写不出 = 接口没想清楚；把类结构写进决策清单 = 预设设计，删除。

### 契约怎么写（DbC 口径）

| 要素 | 问法 | 不合格的样子 |
|---|---|---|
| 前置条件 | 调用方必须保证什么？ | "参数要合法" |
| 后置条件 | 返回时什么是真的？ | "返回结果正确" |
| 不变式 | 调用前后都不能破坏什么？ | 留空（有状态时必填） |
| 错误语义 | 违反前置时抛什么 / 返回什么？ | "处理错误" |

写不出契约 = 接口还没想清楚，回上一步。

**YAGNI 闸门**：任何模式建议先过三问——变化已经发生？不用会失控？删除成本低？任一为否 → 不用模式。默认答案是"先不用"。

**用户明确要求选模式时**（如"这里该不该上策略模式"）：加载 design skill 再谈，结论记进「关键选择」，不写进故事。

---

## 红旗 — 停止

- 用户没批准就推进
- 决策清单含 TBD / 稍后决定
- 对外接口没有前置/后置条件
- 决策清单里出现类拆分 / 组件划分 / 模式选型（属预设设计）

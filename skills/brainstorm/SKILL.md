# Brainstorm — 设计探索方法

通过对话澄清需求、探索方案、逐步确认设计。

**目录**：提问澄清 · 复述确认 · 退出通道 · 提出方案 · 决策清单 · Builder Check · 红旗。

## 提问澄清

聚焦理解四件事：

| 维度 | 问题 |
|------|------|
| 目的 | 为什么做这个？解决什么问题？ |
| 约束 | 时间、技术栈、兼容性要求？ |
| 成功标准 | 怎么知道做对了？ |
| 范围 | 什么明确不做？ |

职责归属、依赖方向与契约写法不在本轮：见 `design/SKILL.md`。

**先开放后选项**：还不知道「为什么」时只问开放问题，**不给选项**（选项会引导答案）。知道 why 之后，若某个决策的候选能明确列出，再给具体选项 + 各自取舍 + 你的推荐，让对方选。

**方式：** 一次只问一个（Builder Check 收口除外）；能从已有上下文找到答案的，不要问。

**反模式：** 一次问多个、模糊问题、跳过问题直接设计、不知道 why 就给选项。

### 复述确认

每理解一块（目标与使用者 / 某段行为 / 某个约束），用 2-3 句复述回去，再问下一块；复述与提问交替进行，不要一次问完。整段对话复述不超过 3 块，避免把 Step 1 拖成多轮。

- 只把对方说过的内容算「他的原话」；你补的推断必须标成「我的理解」，并给出理由。
- 每块复述结尾问一句「哪里不对或还缺什么」。

### 退出通道

用户明确表示不想讨论时：不再逐块提问，一次性给出目标 / 非目标 / 契约 / 关键选择，未确认处列入「未决项」，请用户一次确认。

**不跳过硬门**：仍须用户明确确认决策后才能进入下一步；「不想讨论」只减少提问轮次，不减少产物。轻量档不加载本 skill，不在此处理。

---

## 提出方案

提出 **2-3 个方案**，每个含：描述 / 优势 / 劣势，并按 开发时间 · 复杂度 · 维护成本 · 风险 四维对比。

**YAGNI：** 删除不必要功能，MVP 优先。抽象时机 = 同一坏味道第三次重复（Rule of Three）；模式引入的 YAGNI 三问唯一来源见 `design/SKILL.md`，本文件不复制。

---

## 输出：决策清单

产出**决策清单**。**brainstorm 是决策清单格式的唯一定义源**；`agents/Feature.md` Step 1 引用本格式，不另行定义（对话中给出，不单独写文档）：

```markdown
## 决策清单

**目标**（1-3 行）
**非目标**（1-3 行，明确不做什么）

### 对外接口与契约
| 接口 | 前置条件 | 后置条件 | 不变式 | 错误语义 |
|------|----------|----------|--------|----------|
| `IX.foo(a) → B` | a 非空 | 返回 ≥0 | — | 非法输入抛 E |

### 关键选择
| 选择 | 理由 |
|------|------|
| ... | ... |

### 未决项
- 无 / [条目 + 待谁裁决]
```

| 要素 | 是否进决策清单 |
|------|----------------|
| 目标 / 非目标 | ✅ 必需 |
| 对外接口 + 前置/后置/不变式 | ✅ 必需（唯一的前置设计） |
| 关键选择 + 理由 | ✅ 必需（含范式结论「已定 / 未定」；判定细则见 functional skill） |
| 错误语义 / 边界 | ✅ 必需 |
| **类怎么拆、组件划分、模式选型** | ❌ 不进——留 REFACTOR 由测试压力逼出 |
| 数据流细节 | ⚠️ 仅在影响契约时写一句 |

**红线**：把类结构写进决策清单 = 预设设计，删除。

### 契约怎么写（DbC 口径）

| 要素 | 问法 | 不合格的样子 |
|---|---|---|
| 前置条件 | 调用方必须保证什么？ | "参数要合法" |
| 后置条件 | 返回时什么是真的？ | "返回结果正确" |
| 不变式 | 调用前后都不能破坏什么？ | 留空（有状态时必填） |
| 错误语义 | 违反前置时抛什么 / 返回什么？ | "处理错误" |

**YAGNI 闸门**：任何模式建议先过 `design/SKILL.md` 的三问，本文件不复制；默认答案是「先不用」。

**用户明确要求选模式时**（如"这里该不该上策略模式"）：加载 design skill 再谈，结论记进「关键选择」，不写进故事。

### Builder Check（完整档，定稿前）

决策清单写完、交给用户前，dispatch `oracle`（Feature 已允许，只读），给：清单全文 + 目标一句 + 仓库路径。

```
Task(oracle, "设计缺口检查",
  "## Task: 只报告按这份清单开工前仍必须知道、但清单没写的信息；每条说明答案会如何改变实现。
     已明确留给实现者的、能自行合理决定的、纯措辞问题都不要报。没有就回答「没有」。
   ## Context: <目标一句> + <清单全文> + <仓库路径>")
```

把返回分成三堆：

| 分堆 | 处理 |
|------|------|
| 清单或仓库中已回答 | 补进对应条目，不问用户 |
| 可合理自行决定 | 自己定，标为「我的判断」写进关键选择 |
| 只有用户能答且会改变实现 | 合并成一次提问（最关键的在前；此处为收口，**例外于「一次只问一个」**） |

只做这一轮，不反复派。**仅完整档执行，精简档跳过。**

## 红旗 — 停止

- 用户没批准就推进
- 决策清单含 TBD / 稍后决定
- 对外接口没有前置/后置条件
- 决策清单里出现类拆分 / 组件划分 / 模式选型（属预设设计）

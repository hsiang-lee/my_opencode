# Test Double — 五分类与选择

回到索引: [../SKILL.md](../SKILL.md)

| 类型 | 作用 | 断言什么 | 典型实现 |
|------|------|----------|----------|
| **Dummy** | 只为填参数，永不被调用 | 无 | 空对象 / nullptr 替代 |
| **Stub** | 提供预设返回值 | 无（只控制输入） | 硬编码返回 |
| **Spy** | Stub + 记录调用 | 调用次数 / 参数 | 手写记录器 |
| **Mock** | 预设期望，不符即失败 | 交互是否发生 | 框架生成 |
| **Fake** | 可工作的简化实现 | 状态 | 内存 DB、内存队列 |

## 选择顺序

```
真实对象 → Fake → Stub → Spy → Mock
```

**能用真实对象就不用替身。** 每退一步都要有理由：

| 退到 | 理由 |
|------|------|
| Fake | 真实依赖慢/有副作用，但需要真实行为（如仓储） |
| Stub | 只需要控制某个返回值，不关心交互 |
| Spy | 需要事后确认「有没有调用、参数对不对」 |
| Mock | 交互契约本身就是需求，且期望可预先声明 |

## 判定问题

```
我要验证什么？
├── 状态/结果对不对      → 真实对象 / Fake / Stub + State Verification
└── 是否发出了某个交互    → Spy / Mock + Behavior Verification
```

## 红线

1. **Mock 只验证对外交互**（发请求、写队列、调外部服务），不能验证内部逻辑。
2. `verify(mock).called()` 若没有对应的行为/状态断言 = 假测试（测的是 mock 自身）。
3. Mock 的期望值必须来自需求，不能从实现倒推（否则重构必碎）。
4. 一个测试里 Mock 超过 2 个 → 被测对象依赖太多，先怀疑设计（见 design/grasp 低耦合）。
5. 不要 mock 值对象、数据结构、标准库容器。
6. Fake 必须与真实实现共享契约测试：同一组测试跑两者。

## 常见误用

| 误用 | 后果 | 修正 |
|------|------|------|
| 什么都 mock | 测试全绿但集成必崩 | 只 mock 边界（IO / 时间 / 随机 / 第三方） |
| mock 返回值写死实现细节 | 重构即碎 | 用 Fake 或只断言结果 |
| 用 mock 验证私有方法调用 | 测试与实现耦合 | 通过公共接口断言结果 |
| stub 返回非法值 | 测的是不可能场景 | 替身行为要符合真实契约 |

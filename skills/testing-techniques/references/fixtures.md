# Fixture（夹具）策略

回到索引: [../SKILL.md](../SKILL.md)

## 四种策略

| 策略 | 何时建 | 隔离性 | 速度 | 适用 |
|------|--------|--------|------|------|
| **Fresh** | 每个测试新建 | 最好 | 稍慢 | 默认 |
| **Shared** | 类/套件共享 | 差（状态污染） | 快 | 构造极贵且**只读** |
| **Lazy Setup** | 首次使用时建 | 中 | 快 | 共享但不总用到 |
| **Suite** | 整个套件一次 | 最差 | 最快 | 只读基准数据（如字典表） |

**默认 Fresh。** 共享策略见上表；没有测量证据的「昂贵」不算昂贵。

## 状态污染的症状与代价

- 测试单独跑绿、全量跑红（或顺序变了就红）
- 一个测试改了共享对象，后续测试断言了被污染的值
- 并行执行时随机失败

代价远高于「多构造几次对象」：偶发红会让人开始忽略红色。

## 工厂函数

```cpp
Order make_order(Money amount = Money{100},
                 CustomerTier tier = CustomerTier::REGULAR);
```

规则：
- 默认值要构造出**合法**对象，测试只覆盖关心的字段
- 一个工厂一个概念；参数超过 3 个 → 用 Builder
- 工厂放测试支持目录，不放生产代码
- 不要用工厂隐藏关键输入：测试体里要能看出「这个用例与其他用例的差别」

## 分类组织

```
tests/
  support/factories.hpp      // make_xxx
  support/fakes/             // FakeRepository 等
  unit/                      // 无 IO，毫秒级
  integration/               // 连真实依赖，秒级
```

快慢分离的目的：让「每次改动都跑」的那一层足够快。慢测试只在该跑的时候跑，而不是删掉。

## 红线

- 测试之间通过静态变量/单例/全局状态互相影响 → 改 Fresh
- 夹具里含随机值或当前时间 → 注入固定值（见 `test-smells.md` 不可重复）
- 依赖测试执行顺序（`test_02_...`）→ 独立化
- 在测试里 sleep 等异步 → 用可注入的时钟或轮询断言（有上限）

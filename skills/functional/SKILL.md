# Functional — 函数式思维

不换语言，换表达方式。**表达式 > 语句，不可变 > 可变，组合 > 继承。**

OO 与 FP 正交，不互斥：领域模型用 OO，内部计算用纯函数。

**目录**：1 范式选型 · 2 五个构建块 · 3 错误处理 · 4 微规则 · 5 反 FP 闸门 · 6 语言适配 · 7 评审清单 · 边界

---

## 1. 范式选型

| 问题特征 | 选 |
|----------|----|
| 复杂状态变迁 / 生命周期管理 | OO（实体、状态机） |
| 数据变换 / 过滤 / 聚合 | FP（管道） |
| 多态扩展（插件、策略） | OO（接口 + 多态） |
| 并发安全的数据处理 | FP（不可变数据） |
| 模拟现实实体关系 | OO（组合） |
| 需要数学式推理的纯逻辑 | FP（纯函数） |

---

## 2. 五个构建块

| 构建块 | 作用 | 替代的 OO 结构 |
|--------|------|----------------|
| 高阶函数 | 函数作参数或返回值 | 策略类、命令类 |
| 闭包 | 捕获定义处作用域的变量 | 只为一个方法存在的内部类 |
| 柯里化 | 多参函数拆成单参序列，复用前缀 | 参数对象 + 工厂 |
| 惰性求值 | 真正需要时才计算 | 迭代器（惰性范围更大） |
| 模式匹配 | 按结构分支并解构 | 多态（类型有限且稳定时用匹配） |

## 3. 错误处理

| 容器 | 表达 | 不该用它做的事 |
|------|------|----------------|
| Optional | 可能没有值 | 包装「业务失败的原因」 |
| Either | 失败 + 原因 | 替代全部领域异常的层级设计 |
| Try | 包装可能抛异常的边界 | 层层嵌套、把内部逻辑也塞进去 |

**红线**：不可预期的编程错误仍用异常。不要把错误处理全部改造成容器。

---

## 4. 微规则（6 条）

1. **表达式优先** — 有返回值的写法优于就地修改
2. **管道替代循环** — `map/filter/reduce` 表达意图，避免索引错误
3. **默认不可变** — `const` / `final` / `readonly`，新增而非修改
4. **副作用推边界** — IO / DB / 网络独立成层，核心逻辑纯
5. **纯函数优先** — 同输入同输出，无隐藏状态
6. **小函数组合** — 一个函数只做一次变换

---

## 5. 反 FP 闸门（过度应用即负分）

- 一个表达式内管道超过 **6 段** → 提取具名中间函数
- 嵌套 `reduce` 层级超过 **2 层** → 改写为显式循环或具名函数
- 为单个 lambda 造一个类 → 直接在调用处传函数
- 语言缺乏 FP 设施（如 C）→ 不模拟，用直白写法
- 纯函数化导致需要传 4 个以上上下文参数 → 说明抽象选错了

## 6. 语言适配

| 语言 | 可用设施 |
|------|----------|
| TS / JS | Array 高阶方法、可选链、Promise |
| Java | Stream、Optional、lambda |
| Python | 推导式、生成器、itertools |
| C++ | `std::ranges`、lambda、`std::optional` |
| C | 不适用，不硬套 |

---

## 7. 评审清单（7 项）

- [ ] 能写成表达式的地方没有用语句块+就地修改
- [ ] 遍历数据用管道或 ranges，不是手写索引循环
- [ ] 共享可变状态要么消除，要么有明确同步理由
- [ ] 副作用集中在边界层，核心逻辑可独立测试
- [ ] 没有为单个 lambda 造的类
- [ ] 管道长度 ≤6 段，否则已提取具名函数
- [ ] 语言不支持时未强行模拟 FP
